# Plan: Fix PlayOut Compatibility on Old Windows 10 Machines

## Problem Summary

The PlayOut application (Tauri v2 + Rust + Vue 3) fails on older Windows 10 machines due to three missing runtime prerequisites that are not configured in `tauri.conf.json`.

---

## Root Cause Analysis

### Issue 1: Missing WebView2 Runtime (`tauri.conf.json`)
- **Impact**: App fails silently or crashes at launch with no clear error
- **Cause**: `tauri.conf.json` has no `bundle.windows.webviewInstallMode` configuration
- **Solution**: Add `"webviewInstallMode": "downloadBootstrapper"` (preferred) or `"embedBootstrapper"` for best experience on old machines. Options:
  - `downloadBootstrapper` (recommended): Downloads WebView2 from Microsoft during install (requires internet)
  - `embedBootstrapper`: Embeds the ~1.8MB bootstrapper, still needs internet to download actual runtime
  - `offlineInstaller`: Embeds the full ~170MB WebView2 offline installer — best for air-gapped old machines but increases installer size
  - Recommendation: `downloadBootstrapper` for general case, `offlineInstaller` if machines may be offline

### Issue 2: Missing Visual C++ Redistributable
- **Impact**: Error "VCRUNTIME140.dll not found" / "The application was unable to start correctly (0xc000007b)"
- **Cause**: The Rust MSVC-compiled binary links against `VCRUNTIME140.dll`. Old Windows 10 machines (especially clean installs, LTSC editions, or machines without Microsoft Store/Windows Update) may not have the VC++ 2015-2022 redistributable
- **Solution**: Tauri v2 supports bundling VCRedist via the WiX installer format (`bundle.windows.wix.vcredist`). Switch from default NSIS to WiX-based `.msi` installer with VCRedist bundled.

### Issue 3: Resources Not Bundled with Installer
- **Impact**: App runs but can't find ffmpeg/ffprobe/ffplay — no scanning, no trimming, no preview generation
- **Cause**: `Requirements/ffmpeg/bin/` (ffmpeg.exe, ffprobe.exe, ffplay.exe) and potentially `Requirements/OBS STUDIO/` are gitignored and NOT configured in `bundle.resources`. The app looks for these at `<exe_dir>/Requirements/ffmpeg/bin/` (see `runtime_settings.rs:84-85`)
- **Solution**: Add `"resources"` to `bundle`, stop tracking-only gitignore for `Requirements/*` (keep `Requirements/OBS STUDIO/` ignored if it's 3rd-party)

## Implementation Plan

### Step 1: Update `src-tauri/tauri.conf.json` — Bundle Configuration

Add the following block inside `"bundle"`:

```
"bundle": {
  "active": true,
  "targets": "all",
  "icon": [...existing...],
  "resources": {
    "Requirements/ffmpeg/bin/*": "Requirements/ffmpeg/bin/"
  },
  "windows": {
    "webviewInstallMode": {
      "type": "downloadBootstrapper"
    },
    "wix": {
      "language": "en-US",
      "vcredist": true
    }
  }
}
```

**What each setting does:**
- `resources`: Bundles ffmpeg.exe/ffprobe.exe/ffplay.exe next to the executable at `Requirements/ffmpeg/bin/`
- `windows.webviewInstallMode`: Downloads and installs WebView2 if not present (requires internet); alternative `type: "offlineInstaller"` for offline
- `windows.wix`: Generates an `.msi` installer instead of `.nsis`; `vcredist: true` bundles the Microsoft VC++ Redistributables

### Step 2: Fix `.gitignore`

Keep `Requirements/` gitignored. The ffmpeg binaries will be fetched by a build-time script instead, keeping the repo lean.

### Step 3: Create Build-Time FFmpeg Download Script

Create `scripts/download-ffmpeg.ps1` that:
- Downloads a Windows ffmpeg build (e.g., from gyan.dev — essential LGPL build)
- Extracts to `Requirements/ffmpeg/`
- Is called as a `beforeBuildCommand` or prerequisite step

The `tauri.conf.json` `beforeBuildCommand` should be updated to run this script before bundling:
```json
"beforeBuildCommand": "powershell -ExecutionPolicy Bypass -File scripts/download-ffmpeg.ps1 && npm run build"
```

### Step 4: Verify Build Output

Run `npm run tauri build` and verify the `.msi` installer:
- Contains `Requirements/ffmpeg/bin/` in the install directory
- Bundles VCRedist merge module
- Includes WebView2 bootstrapper

### Step 5: Test on Target Windows 10 Machines

Validate on at least:
- Clean Windows 10 LTSC (most likely to lack WebView2 + VCRedist)
- Windows 10 without recent updates

## Configuration Reference: Full `tauri.conf.json` Bundle Section

The final bundle section should look like:

```json
"bundle": {
  "active": true,
  "targets": "all",
  "icon": [
    "icons/32x32.png",
    "icons/128x128.png",
    "icons/128x128@2x.png",
    "icons/icon.icns",
    "icons/icon.ico"
  ],
  "resources": {
    "Requirements/ffmpeg/bin/*": "Requirements/ffmpeg/bin/"
  },
  "windows": {
    "webviewInstallMode": {
      "type": "downloadBootstrapper"
    },
    "wix": {
      "language": "en-US",
      "vcredist": true
    }
  }
}
```

**Prerequisite tools for WiX build:** Developer must have [WiX Toolset v3](https://wixtoolset.org/releases/) installed (`wix311-binaries.zip` or via `cargo install cargo-wix`). The `tauri build` command will auto-detect WiX or prompt for installation.

---

## Tradeoffs

Chosen approach: `downloadBootstrapper` for WebView2 (internet required during install) + WiX with VCRedist + build-time ffmpeg script.
- Installer size: ~50MB for app + Windows shells framework (~40MB WiX bootstrapper)
- Target machines need internet during setup (for WebView2 download, ~130MB)
- Clean repo — ffmpeg binaries not committed, fetched during build
- Manual offline workaround: pre-install WebView2 (Microsoft offline installer) + VC++ Redist before running the MSI
